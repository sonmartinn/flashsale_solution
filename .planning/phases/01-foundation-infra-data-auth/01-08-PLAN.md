<objective>
Close UAT gap G-01-2. The user asked for a thorough fix ("sửa triệt để"): every startup failure must end with exactly one Vietnamese `[LỖI]` line on stderr, for the server, `npm run seed` and `npm run reset`, while runtime Redis disconnects after boot are still logged.

Root cause (diagnosed): `createRedis()` (`backend/src/config/redis.ts:19-24`) attaches its logging `error` listener when the client is constructed, with no boot gating, and the first error always passes the rate limiter. ioredis 6 always emits the connection error as an `error` event before `connect()` rejects, so every Redis startup failure (ECONNREFUSED, ETIMEDOUT, ENOTFOUND, ECONNRESET, bad RESP, NOAUTH) prints `[Redis] mất kết nối: ...` before the caller's `[LỖI]` line. A related defect: a Redis endpoint that accepts TCP but never answers makes boot hang silently, because `connectTimeout` covers only the TCP open and `connectRedis` has no overall deadline. That violates D-19. The existing tests only regex-match `[LỖI]` somewhere in stderr, so the extra line passed.

Mechanism (the diagnosis's suggested route, applied in one place):
- `createRedis` keeps a silent `error` listener from creation, because one must exist or ioredis prints `[ioredis] Unhandled error event` with a stack.
- `connectRedis` wraps connect and PING in a startup deadline (`REDIS_STARTUP_TIMEOUT_MS = 5000`) and arms the existing rate-limited logger only after both succeed.

server.ts, seed.ts and reset.ts already share `createRedis`/`connectRedis`, so they need no change. The MongoDB-down, port-held and JWT paths already print one line (createRedis runs after them). This plan pins them with exact line-count tests, as the user asked.

Output: the redis.ts fix, three test helpers (`stderrLines`, `startFakeRedis`, `spawnCli`), a Docker-free in-process matrix (`redis.test.ts`), exact line-count assertions in boot.test, health.test and models.test, and an integration matrix (`redis-boot.test.ts`) for the compiled server, both CLIs and the runtime proxy-cut case.

Decisions implemented: D-19 (fail-fast: connectTimeout 5000, maxRetriesPerRequest 1, startup PING, no `retryStrategy: () => null`, now also an overall startup deadline), D-18 (clear Vietnamese exit for each missing or unreachable dependency), D-07/DATA-05 (reset's cache warning is always printed), D-21 (the index-creation failure exits with one line).
</objective>
