<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| client -> /api/admin/* | Only admin JWTs may reset stock or read stats; test-mode identities must not pass |
| admin reset body -> sale-admin service | Untrusted JSON chooses the sale mode |
| admin reset -> in-process cache | A reset changes static sale fields the buy path reads from cache |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-02-14 | Elevation of privilege | POST reset / GET stats | high | mitigate | router.use(requireAuth, requireAdmin) stays the first statement of the admin router; tests assert 401 without a token and 403 for a user JWT and for x-test-user |
| T-02-15 | Tampering | reset request body | medium | mitigate | body must be a non-array object; only `mode` is read and must be a string in SALE_MODES (INVALID_MODE otherwise); id normalized by the service; tests cover null, number, array and wrong-case values |
| T-02-16 | Denial of service | an admin reset during a measurement | low | accept | admin-only action; the Phase 3 harness controls when resets happen; documented as a mode-mixing risk (Phase 5) |
| T-02-17 | Information disclosure | stats response | low | accept | admin-only, returns counts and the sale mode/status only, no user ids or emails |
| T-02-SC | Tampering | npm installs | high | mitigate | no new packages; only npm ci from the existing lockfile |
</threat_model>
