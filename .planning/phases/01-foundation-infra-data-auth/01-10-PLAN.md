<objective>
Close the single gap in 01-VERIFICATION.md (`gaps:` entry 1, status partial). It is 01-09 must-have 2, the drift guarantee, and it is the same finding as REVIEW WR-02, which is still open. This plan's gap ID is **G-01-V1**: the first verification-sourced gap of phase 01. It is not a UAT test number, so it cannot collide with the G-01-{test} IDs.

The problem: `serverArgv("start:test")` in `backend/test/helpers.ts` hard-codes the dotenv wrapper argv, and `build.test` only pins `package.json` to `START_TEST_SCRIPT`. Suppose someone edits the script and the constant together, for example dropping `--override`. build.test and every `launcher: "start:test"` case, including the G-01-9 regression test, would stay green while the real `npm run start:test` stops forcing test mode. The helper's doc comment claims the opposite.

The fix takes both routes the VERIFICATION `missing:` list names:
- Derive the argv from the constant. A new exported pure function `startTestArgv(script)` replays the script's last `&&` segment, maps four tokens to absolute or runnable equivalents, and throws on anything it cannot replay faithfully. `serverArgv` calls it with `START_TEST_SCRIPT`.
- Pin the derivation in build.test, so the constant-to-argv direction is asserted explicitly and does not rest on reading the helper.

Then correct the doc comments, including WR-02's second point: the helper deliberately runs `process.execPath` where npm runs `node` from PATH. Finally prove the gap scenario end to end with two coordinated mutations, and record WR-02 as fixed.

Not in this plan:
- The G-01-9 human re-test in 01-VERIFICATION `human_verification` is unchanged. It still has to be run by a person. This plan adds no human check.
- The real `npm run start:test`, `backend/src`, `backend/scripts` and the committed `.env.test` are not touched.

Decisions honoured: D-20 (the constant is the D-20 script, and the script stays byte-identical), D-14 (env.ts stays the single test-mode site), D-18/D-19 (a start:test boot failure still gives one `[LỖI]` line, now through the derived argv and proven by the `-q` mutation).
