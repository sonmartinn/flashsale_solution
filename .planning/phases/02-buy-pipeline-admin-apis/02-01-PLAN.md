<objective>
Let a logged-in user buy one unit through `POST /api/sales/:id/buy?mode=v0|v1|v2` with one shared check sequence, one static sale cache and one order-creation function, so the three stock strategies differ only in the stock step and answer with identical codes.

Purpose: This is the never-cut core (V0, V1, V2) that Phase 3's E1/E2 measure. V0 must visibly oversell, V1 and V2 must never exceed `totalQty`, and the comparison must be fair (same cache read, same validation, same `createOrder`, no log on the buy path).
Output: Five Phase 2 error codes, the `flashBuy` typing and Lua registration (boot + tests), the single-flight sale cache, `createOrder`, the purchase service with `buyHandlers` v0/v1/v2, the buy controller and route, and the `buy.test` / `lua.test` integration suites.

Decisions implemented: D-01, D-02, D-03 (no mode-mismatch guard), D-04, D-05, D-06, D-07, D-08, D-09, D-13, D-14, D-15, D-16, D-17, D-18, D-19 (buy never reads mode-specific data through the cache), D-20 (OrderDto), D-32, D-33, D-34.
