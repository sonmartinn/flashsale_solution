<objective>
Let anyone browse products and open sales (with the right `remaining` for the sale's mode and the server time), and let a logged-in user see their own orders.

Purpose: Phase 4's home page, sale page (countdown corrected by server `now`, Buy button following `sale.mode`, remaining count) and orders page render exactly these shapes; reading V2 stock from Redis is the only way the UI can show the truth, because V2 never touches `remainingQty`.
Output: `stock.service.ts` (remaining by mode), `catalog.service.ts`, DTO mappers, product/sale/order controllers and routes, mounting in `routes/index.ts`, and `read.test.ts`.

Decisions implemented: D-19 (reads hit MongoDB fresh, never the buy cache), D-20, D-21, D-22, D-23, D-32.
Claude's-discretion choices recorded here: `/orders/me` gets its product summaries from one `Product.find({ _id: { $in } })` plus a Map, not `populate` (RESEARCH: populate would replace `productId` with an object and break `OrderDto.productId: string`); a sale or order whose product document no longer exists is a data-integrity error and answers 500 (the seed always creates both together), so `product` is never null in the D-20 shapes.
This plan runs in wave 3 only because it shares `backend/src/routes/index.ts` with plan 02-04; it has no logic dependency on 02-03 or 02-04.
Sizing (plan-checker warning, revision 1): this plan has 3 tasks, not 4 (`verify.plan-structure` reports task_count 3, matching `estimate.tasks`). Its 70k-token estimate is below the 100k smart-zone budget (`workflow.smart_zone_tokens`, project default; estimate calibration has no samples yet, factor 1). Most files per task are thin factories: the existing `routes/auth.routes.ts` and `controllers/auth.controller.ts` are 13 and 14 lines, and the new product/order router and controller copy that shape. The rest is the shared `read.test.ts` and one mount line in `routes/index.ts`. A split would not lower the peak much. Every task edits `catalog.service.ts`, `routes/index.ts` and `read.test.ts`, so a split-off plan would have to run in a fourth wave after this one.
</objective>
